# Дизайн

## Линтер

За основу берётся `.golangci.yml` ядра (формат v2, `default: all` с явным
списком отключений) — это сохраняет настройки кодстайла одинаковыми между
Go-сервисами MarketVision и упрощает переход разработчиков между репозиториями.
Конфиг рассчитан на golangci-lint v2 линейки до ~2.4: проверено на v2.4.0,
где исключение `exhaustruct.exclude` для `net/http.Server` ещё применяется.
В свежих версиях (2.13+) старые настройки этого линтера игнорируются после
переезда на движок v5, поэтому обновление версии должно сопровождаться
миграцией конфига в обоих репозиториях согласованно.

Из конфига ядра убираются специфичные для него исключения путей
(`internal/adapters/http/v1`, где лежит сгенерированный по swagger-контракту
код); когда в Ozon-сервисе появится генерируемый код, соответствующие пути
добавляются в `exclusions.paths` вместо ослабления общих правил.

Правило `line-length-limit: 120` соответствует текущему стилю файлов сервиса
(README, AGENTS.md уже используют подобную ширину строк).

## Taskfile

Используется `go-task` (уже установлен как стандартный инструмент; ядро также
использует `Taskfile.yml` версии `3`). Состав задач:

- `build` — компиляция бинарника в каталог вне контроля версий
  (`bin/ozon-service`), чтобы команда проверяла сборку без запуска;
- `run` — запуск приложения через `go run ./cmd/app/main.go` без зависимости от
  миграций (БД в сервисе пока не появилась);
- `lint` — `golangci-lint run`; ожидается локально установленный бинарь,
  пин версии не задаётся до появления CI;
- `test` — `go test ./...`;
- `generate` — `go generate ./...`; на текущем этапе директив в коде нет,
  задача становится точкой входа под будущую кодогенерацию (gRPC-схемы, моки),
  описанную в OpenSpec контракта ozon-service ↔ ядро.

Задачи намеренно не включают docker compose и миграции: инфраструктура сервиса
появится отдельными изменениями.

## Совместимость

Изменение добавляет только файлы конфигурации и не влияет на поведение кода,
HTTP-сервера или тестов. Обратная совместимость с командами из README
(`go test ./...`, `go vet ./...`) сохраняется.
