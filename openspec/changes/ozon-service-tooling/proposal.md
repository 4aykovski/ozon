# Настройка линтера и Taskfile для Ozon-сервиса

## Почему

Каркас сервиса создан, но инструменты качества и локальной разработки
отсутствуют. Без единого конфига линтера проверки стиля зависят от локальных
настроек разработчика, а без Taskfile команды сборки, запуска, тестов,
проверок и кодогенерации не зафиксированы. Ядро уже использует `golangci-lint`
и `go-task`, поэтому Ozon-сервис выравнивается с ним по рабочему окружению.

## Что меняется

- добавляется `.golangci.yml` на основе конфигурации ядра (формат v2);
- добавляется `Taskfile.yml` с задачами: `build`, `run`, `lint`, `test`,
  `generate`;
- задача `generate` резервируется под будущую кодогенерацию (gRPC-контракты,
  моки) и на текущем этапе выполняет `go generate ./...` по наличию директив;
- запуск линтера входит в локальную проверку изменений наравне с
  `go test ./...`.

## Не входит в изменение

- реализация Ozon Seller API и синхронизации данных;
- добавление gRPC/proto-контрактов и самих генераторов (только точка входа
  под них в Taskfile);
- настройка CI/CD (покрывается задачей OPS-9);
- изменения в ядре.
