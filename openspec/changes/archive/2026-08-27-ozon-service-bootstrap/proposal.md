# Перенос внутренних пакетов и документирование каркаса Ozon-сервиса

## Почему

После создания базового каркаса нужно закрепить границы пакетов и архитектурный
контекст сервиса. Пакеты, используемые только внутри сервиса, не должны
выглядеть как публичный API. Описание текущего и целевого устройства нужно
хранить рядом с кодом, чтобы дальнейшие изменения опирались на решения команды
Development из Linear.

## Что меняется

- пакетный слой переносится из `pkg/` в `internal/pkg/`;
- README описывает назначение сервиса, текущий Ozon-поток и целевую архитектуру;
- добавляется `AGENTS.md` с правилами Linear, OpenSpec и approval для staging и
  production;
- `AGENTS.md` фиксирует работу только в ветке задачи и обязательное создание
  задачи в Linear, если кодовая задача пришла без идентификатора;
- добавляется конфигурация OpenSpec и checklist этого изменения.

## Не входит в изменение

- реализация Ozon Seller API;
- добавление базы данных, gRPC/protobuf-контрактов или отчётных формул;
- деплой и создание/изменение staging или production окружений.
