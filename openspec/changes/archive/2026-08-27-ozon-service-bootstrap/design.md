# Дизайн

## Границы пакетов

Все текущие пакеты сервиса находятся под `internal/`. Пустой расширяемый слой
`internal/pkg` сохраняется как место для переиспользуемых пакетов, которые не
являются частью внешнего API Go-модуля. Точка входа остаётся в `cmd/app`, а
lifecycle и HTTP-заглушка — в `internal/app`.

## Документация

README фиксирует два состояния архитектуры: текущий переходный поток через
Ozon-ручку ядра и целевое разделение на marketplace-, users- и report-сервисы.
AGENTS.md формализует операционные ограничения для последующих изменений:
задачи и архитектурные решения сверяются с Linear, статус задачи синхронизируется
с фактическим этапом работы, изменения оформляются и проводятся через OpenSpec,
новая кодовая работа получает задачу в Linear, работа из `main` начинается в
отдельной ветке, а любые действия в staging/production требуют явного approval
независимо от уровня доступа.

## Совместимость

Перенос не меняет поведение HTTP-сервера и не добавляет внешних зависимостей.
Изменение влияет только на путь внутреннего пакета; внешний импорт такого
пакета и не должен поддерживаться Go-правилами `internal`.
